# CLAUDE.md

PennyTrace is a local-first Android expense tracker. It builds a ledger automatically from bank and UPI SMS. Nothing leaves the phone except a model download that the user starts by tapping.

The full design is in [`plan.md`](plan.md). Read it before making architectural changes.

## Stack

- **App:** React Native CLI **0.87.1**, bare (not Expo), TypeScript strict, New Architecture, Hermes. Android only.
- **Navigation:** `@react-navigation/*` v7.
- **State:** `zustand`.
- **Database:** `@op-engineering/op-sqlite` with SQLCipher (`"op-sqlite": {"sqlcipher": true}` in package.json) and `drizzle-orm`. Migrations are generated by `drizzle-kit`.
- **On-device LLM:** `llama.rn` (GGUF). Use JSON-schema-constrained output only.
- **Native code:** Kotlin, under `android/app/src/main/java/com/pennytrace/`.
- **Icons:** Material Symbols Rounded SVGs from `@material-symbols/svg-400`, imported as components through `react-native-svg-transformer`.
- **Fonts:** Geist and Geist Mono, bundled in `android/app/src/main/assets/fonts`. Reference them by file name, e.g. `fontFamily: 'Geist-SemiBold'`. Do not combine a family with `fontWeight`.

## Layout and boundaries

```
src/core/      PURE TypeScript ledger engine: types, parsers, pipeline, ledger math. No React Native imports (ESLint enforced).
src/db/        op-sqlite + drizzle schema, migrations, repositories, SQLCipher key bootstrap
src/native/    TurboModule specs (codegen), e.g. PennySms
src/llm/       model manager, download (the ONLY network code), constrained-output tasks
src/ui/        theme tokens (from the Ledger design), primitives, charts, icons
src/features/  screens: today, review, activity, detail, insights, accounts, privacy, onboarding, model, chat
src/app/       navigation, providers, stores
fixtures/sms/  anonymised SMS samples + expected parse results (golden tests)
```

- `src/core/types.ts` is the contract between every layer. If you change its semantics, bump the parser or ledger version so stored data gets reprocessed.
- Keep business rules in `src/core`. Screens only render view models: `DailyClose`, `Insights`, `AccountRecon`, `Position`, `Transaction`.
- Native modules do platform I/O only: reading SMS, waking on a new SMS, posting notifications. All parsing and ledger logic stays in TypeScript.

## Non-negotiable rules

1. **No network.** `fetch`, `XMLHttpRequest`, `WebSocket` and `EventSource` are banned by ESLint everywhere except `src/llm/download.ts`. Never add analytics, crash reporting, Firebase, remote config, or any other SDK that phones home. `network_security_config.xml` allows HTTPS to Hugging Face hosts only.
2. **Money is integer paise.** Never use floats for amounts. Use the helpers in `src/core/money.ts`.
3. **The ledger is derived and idempotent.** Transactions and transfer links are rebuilt from `source_events`, user overrides and rules. Processing the same SMS again must never change the ledger.
4. **Deduplication:**
   - Never merge two transactions only because they have the same amount on the same day.
   - Merge by a reference (UPI, UTR or RRN), or by a tight time window when both lack references *and* come from different senders or templates.
   - An identical SMS body is caught by its fingerprint.
5. **Never fabricate reconciliation.**
   - Report a variance; don't invent a transaction to cover it.
   - The LLM never produces numbers that are shown as facts: every amount it extracts must appear literally in the source text.
6. **Self transfers, card bill payments and ATM withdrawals are not spending.** Pending transfers are "in transit", never counted as spending.
7. **Privacy of samples.** Run real SMS through `scripts/anonymize-sms.ts` before committing anything under `fixtures/`. Names, account digits, VPAs and references must be masked.
8. **Licence.** The project is AGPL-3.0. Any file ported from pennywiseai-tracker must carry this header:
   `// Ported from pennywiseai-tracker (https://github.com/sarim2000/pennywiseai-tracker), AGPL-3.0. Modified for PennyTrace.`
   Credit them in `NOTICE.md` if you port a new area. Never use the "PennyWise" name or logo.

## Design source

The UI ports the Claude Design project `5134310b-45e3-4ad9-9bf6-6f20714c1678`. `LedgerApp2.dc.html` holds the screens; `Ledger Showcase v2.dc.html` is the canvas that renders them. Local copies are in `design/`.

- Token values are in `src/ui/theme`. Use the tokens; never hard-code colours in screens.
- Number formatting:
  - Indian digit grouping: `en-IN`.
  - Currency symbol: `₹`.
  - Minus sign: U+2212 `−`, not a hyphen.
  - Masked account numbers: `••1234`.
  - Numbers use `tabular-nums`.
  - Raw SMS text, references and parser ids use Geist Mono.

## Commands

```bash
npm start                 # Metro
npm run android           # build + install debug (needs ANDROID_HOME, emulator/device)
npm test                  # all jest projects
npm run test:core         # pure ledger engine only (fast, Node)
npm run typecheck
npm run lint
npm run db:generate       # drizzle-kit: regenerate SQL migrations after editing src/db/schema.ts
npm run audit:permissions # verify release APK permissions against the allowlist
```

- `llama.rn` downloads its native libraries in a postinstall step that npm's allowScripts may block. Approve it with `npm install-scripts approve llama.rn && npm rebuild llama.rn`. F-Droid builds set `rnllamaBuildFromSource=true` in `android/gradle.properties`.
- Seed test SMS on an emulator: `adb emu sms send AX-HDFCBK "Rs.349.00 debited from a/c **1234 ..."`.

## Testing expectations

- **Parser change:** add or extend a golden fixture in `fixtures/sms/<bank>/`.
- **Ledger change:** add a scenario test in `src/core/ledger/__tests__/`. Every scenario asserts the daily-close numbers, and the property test (shuffle or rescan gives the same ledger) must keep passing.
- **Device test:** run the release APK in airplane mode. Everything except the model download must still work.
